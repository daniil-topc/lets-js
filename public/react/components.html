Компоненты и JSX

React собирает страницу из компонентов. В этой главе разберёмся, что это такое, как их писать и почему разметка лежит прямо внутри JavaScript.

Что такое React

React это библиотека для JavaScript, которая помогает собирать интерфейсы. В обычном JavaScript ты сам находишь элемент на странице и меняешь его. В React ты описываешь, как страница должна выглядеть при текущих данных, и библиотека сама приводит её к этому виду.

Сравни два способа показать число кликов. Слева ты командуешь страницей шаг за шагом. Справа описываешь результат.

// Обычный JavaScript: находим элемент и меняем его руками
const counter = document.querySelector('#counter');
counter.textContent = `Кликов: ${clicks}`;

// React: описываем, что должно быть на экране
<p>Кликов: {clicks}</p>

Перед React стоит разобраться с JavaScript: переменные, функции, массивы и объекты здесь нужны на каждом шагу. Всё это есть в справочнике по JavaScript.

Как запустить проект

Браузер не понимает React-код напрямую, его сначала нужно собрать. Проще всего взять готовый инструмент Vite. Три команды в терминале создают проект и открывают его в браузере.

npm create vite@latest my-app -- --template react
cd my-app
npm install && npm run dev

Компонент

Представь конструктор. Из одинаковых деталей можно собрать и дом, и машину. В React такие детали называются компонентами: кнопка, карточка товара, шапка сайта. Ты описываешь деталь один раз и ставишь её в любое место страницы.

Компонент пишется как обычная функция. Она возвращает разметку, которую нужно показать.

function Welcome() {
  return <h1>Привет, новичок!</h1>;
}

// Используем компонент как свой собственный тег
function App() {
  return (
    <div>
      <Welcome />
      <Welcome />
    </div>
  );
}

Имя компонента всегда пиши с большой буквы. По этому признаку React отличает твой <Welcome /> от обычного тега вроде <div>.

JSX

Разметка внутри функции похожа на HTML, но это JSX: расширение JavaScript, которое позволяет писать теги прямо в коде. Главная его возможность скрыта в фигурных скобках. Всё, что стоит внутри { }, выполняется как JavaScript, и результат попадает на страницу.

function Profile() {
  const name = 'Аня';
  const tasks = 3;

  return (
    <div>
      <h2>Привет, {name}!</h2>
      <p>Задач на сегодня: {tasks}</p>
      <p>Если сделать две, останется {tasks - 2}</p>
    </div>
  );
}

В поле ниже лежит значение переменной name. Меняй его и смотри, как меняется результат.

Правила JSX

JSX строже, чем HTML. Запомни четыре отличия, и большинство ошибок новичка тебя обойдёт.

ПравилоВ HTMLВ JSX
Класс пишется иначеclass="card"className="card"
Каждый тег закрыт<img><img />
События в camelCaseonclickonClick
Один корневой тегсколько угодноодин, либо <>...</>

Последнее правило встречается чаще всего. Компонент возвращает один элемент. Если обёртка в виде div не нужна, используй пустой тег, он называется фрагментом и на страницу не попадает.

function Price() {
  return (
    <>
      <span className="price">7 900 ₽</span>
      <span className="old-price">9 900 ₽</span>
    </>
  );
}
Реальный кейс

Карточка товара в интернет-магазине

В каталоге сотни товаров, и у всех карточек одинаковое устройство: фото, название, цена, кнопка. Карточку описывают одним компонентом и собирают из неё всю витрину. Когда дизайнер попросит поменять кнопку, правка в одном месте обновит все карточки сразу.

function ProductCard() {
  const title = 'Наушники';
  const price = 7900;

  return (
    <article className="card">
      <img src="/img/headphones.jpg" alt={title} />
      <h3>{title}</h3>
      <p>{price.toLocaleString('ru-RU')} ₽</p>
      <button>В корзину</button>
    </article>
  );
}
