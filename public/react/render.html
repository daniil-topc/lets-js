Условия и списки

Интерфейс редко бывает неизменным. Одни блоки появляются по условию, другие повторяются столько раз, сколько элементов пришло в данных.

Условный рендеринг

Часть интерфейса часто нужно показывать только при каком-то условии: сообщение об ошибке, значок «Нет в наличии», меню для вошедшего пользователя. Внутри JSX нельзя написать if, зато работают два оператора из JavaScript.

Оператор && показывает элемент, когда условие истинно. Тернарный оператор выбирает один вариант из двух.

function Product({ inStock, discount }) {
  return (
    <div>
      {discount > 0 && <span className="badge">Скидка {discount}%</span>}

      {inStock ? <button>В корзину</button> : <p>Нет в наличии</p>}
    </div>
  );
}

Когда вариантов больше двух или внутри много разметки, обычный if перед return читается легче.

function Status({ state }) {
  if (state === 'loading') return <p>Загрузка…</p>;
  if (state === 'error') return <p>Что-то пошло не так</p>;

  return <p>Готово</p>;
}

Списки

Данные обычно приходят массивом, а на странице нужен список элементов. Метод map превращает каждый элемент массива в кусок разметки. Сам метод разобран в главе про массивы.

function Menu() {
  const dishes = ['Борщ', 'Плов', 'Сырники'];

  return (
    <ul>
      {dishes.map((dish) => (
        <li key={dish}>{dish}</li>
      ))}
    </ul>
  );
}

Зачем нужен key

Каждому элементу списка нужен пропс key с уникальным значением. Представь гардероб: номерок помогает найти своё пальто, даже если вешалки переставили. По ключу React понимает, какой элемент остался на месте, какой добавили, а какой убрали, и обновляет только нужные.

Лучший ключ это id из данных. Индекс элемента в массиве для этой роли подходит плохо: после удаления или сортировки индексы сдвигаются, и React путает элементы между собой.

const tasks = [
  { id: 1, text: 'Купить хлеб' },
  { id: 2, text: 'Выучить useState' },
];

{tasks.map((task) => (
  <li key={task.id}>{task.text}</li>
))}
Реальный кейс

Список задач с фильтром

Здесь сходится всё из этой и прошлой главы. Задачи лежат в состоянии массивом объектов. Клик по задаче создаёт новый массив, где у неё поменялась отметка. Фильтр хранится отдельно, а видимый список вычисляется из задач и фильтра.

function TodoList() {
  const [tasks, setTasks] = useState([
    { id: 1, text: 'Прочитать про key', done: true },
    { id: 2, text: 'Написать свой список', done: false },
  ]);
  const [onlyActive, setOnlyActive] = useState(false);

  function toggle(id) {
    setTasks(tasks.map((task) =>
      task.id === id ? { ...task, done: !task.done } : task
    ));
  }

  const visible = onlyActive ? tasks.filter((task) => !task.done) : tasks;

  return (
    <>
      <label>
        <input
          type="checkbox"
          checked={onlyActive}
          onChange={(e) => setOnlyActive(e.target.checked)}
        />
        Только невыполненные
      </label>

      {visible.length === 0 && <p>Всё сделано</p>}

      <ul>
        {visible.map((task) => (
          <li key={task.id} onClick={() => toggle(task.id)}>
            {task.done ? '✓' : '○'} {task.text}
          </li>
        ))}
      </ul>
    </>
  );
}
