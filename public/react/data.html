Данные и свои хуки

В последней главе компонент получает данные с сервера, а повторяющаяся логика переезжает в собственный хук.

Загрузка данных

Почти каждое приложение получает данные с сервера. Запрос это эффект, поэтому он живёт в useEffect. Сам fetch и async / await разобраны в главе про асинхронность.

У запроса три исхода, и для каждого нужно своё состояние: данные ещё грузятся, данные пришли, случилась ошибка. Если забыть про первый и третий, человек увидит пустой экран и не поймёт, что происходит.

function Tip() {
  const [tip, setTip] = useState(null);
  const [error, setError] = useState(null);

  useEffect(() => {
    async function load() {
      try {
        const response = await fetch('/api/tip');
        if (!response.ok) throw new Error(response.status);
        setTip(await response.json());
      } catch (err) {
        setError('Не удалось загрузить совет');
      }
    }

    load();
  }, []);

  if (error) return <p>{error}</p>;
  if (!tip) return <p>Загрузка…</p>;

  return <p>{tip.text}</p>;
}

В больших проектах запросы обычно отдают готовым библиотекам вроде TanStack Query. Они сами кэшируют ответы и повторяют неудачные запросы. Но устроены они на тех же хуках, поэтому сначала стоит понять ручной способ.

Свои хуки

Когда одна и та же связка из состояния и эффекта нужна в нескольких компонентах, её выносят в отдельную функцию. Если имя функции начинается с use и внутри она вызывает другие хуки, это твой собственный хук. Компоненты пользуются им так же, как встроенными.

Реальный кейс

Форма, которая помнит введённое

Человек начал заполнять анкету и случайно закрыл вкладку. Обидно вводить всё заново. Хук useLocalStorage работает как useState, только каждое значение сохраняет в хранилище браузера и при следующем открытии берёт его оттуда.

function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    const saved = localStorage.getItem(key);
    return saved !== null ? JSON.parse(saved) : initialValue;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}

function Profile() {
  const [name, setName] = useLocalStorage('name', '');

  return <input value={name} onChange={(e) => setName(e.target.value)} />;
}

Контекст

Некоторые данные нужны сразу многим компонентам: тема оформления, язык, текущий пользователь. Передавать их пропсами через пять уровней вложенности неудобно. Контекст работает как радио: один компонент вещает значение, а любой компонент ниже по дереву может на него настроиться.

import { createContext, useContext, useState } from 'react';

const ThemeContext = createContext('light');

function App() {
  const [theme, setTheme] = useState('dark');

  return (
    <ThemeContext.Provider value={theme}>
      <Page />
    </ThemeContext.Provider>
  );
}

// Компонент на любой глубине получает значение напрямую
function Header() {
  const theme = useContext(ThemeContext);

  return <header className={`header header--${theme}`}>let's React</header>;
}

Контекст подходит для данных, которые меняются редко. Для всего остального хватает пропсов и состояния, и код с ними проще читать.

Что дальше

Теперь ты знаешь основу, на которой держится любое React-приложение. Дальше стоит собрать что-нибудь своё: список дел, каталог с фильтром, погоду по городу. На практике быстро всплывут три темы, которые в этот справочник не вошли.

  • Маршрутизация, чтобы у приложения было несколько страниц. Самая известная библиотека называется React Router.
  • Хук useReducer для состояния со сложной логикой.
  • Официальная документация на react.dev, там есть учебник с задачами.
