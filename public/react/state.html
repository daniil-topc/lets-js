Состояние и события

Состояние это память компонента. Благодаря ему кнопка помнит, сколько раз её нажали, а поле знает, что в нём написано.

События

Чтобы компонент реагировал на клик, передай функцию в пропс onClick. React вызовет её, когда человек нажмёт на элемент. Для ввода текста есть onChange, для отправки формы onSubmit.

function BuyButton() {
  function handleClick() {
    console.log('Покупка оформлена');
  }

  return <button onClick={handleClick}>Купить</button>;
}

Передавай саму функцию, без скобок: onClick={handleClick}. Запись onClick={handleClick()} вызовет функцию сразу при показе компонента, до всякого клика.

useState

Обычная переменная внутри компонента ничего не помнит. При каждом показе функция запускается заново, и переменная создаётся с нуля. К тому же React не узнает, что она изменилась, и страницу не обновит.

Для данных, которые меняются со временем, есть состояние. Думай о нём как о памяти компонента. Функция useState возвращает пару: текущее значение и функцию, которая его меняет. Когда ты вызываешь эту функцию, React запоминает новое значение и перерисовывает компонент.

import { useState } from 'react';

function Counter() {
  //     значение  как менять        начальное значение
  const [count,    setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Нажато: {count}
    </button>
  );
}

Эта кнопка работает так же, как компонент Counter из примера.

Функции, имя которых начинается с use, называются хуками. Вызывай их только на верхнем уровне компонента. Внутри условий, циклов и вложенных функций хуки не работают.

Как правильно обновлять состояние

Состояние меняется только через функцию из пары. Если присвоить значение напрямую, React этого не заметит и экран останется прежним.

count = count + 1;      // экран не обновится
setCount(count + 1);    // правильно

С массивами и объектами правило то же. Создавай новую копию с изменениями, старую не трогай. Оператор ... копирует содержимое в новый массив или объект.

const [items, setItems] = useState(['Хлеб']);
const [user, setUser] = useState({ name: 'Аня', age: 25 });

items.push('Молоко');                    // так нельзя
setItems([...items, 'Молоко']);          // новый массив

user.age = 26;                           // так нельзя
setUser({ ...user, age: 26 });           // новый объект

Если новое значение зависит от старого, передай в функцию стрелку. React подставит в неё самое свежее значение.

setCount((prev) => prev + 1);

Кнопка «Нравится»

Под постом в соцсети сердечко и число лайков. В состоянии лежит один факт: поставил человек лайк или нет. Цвет кнопки и число на ней вычисляются из этого факта при каждой перерисовке.

function LikeButton({ likes }) {
  const [liked, setLiked] = useState(false);

  return (
    <button
      className={liked ? 'like is-liked' : 'like'}
      onClick={() => setLiked(!liked)}
    >
      {liked ? '♥' : '♡'} {likes + (liked ? 1 : 0)}
    </button>
  );
}

Поля ввода

Текст в поле тоже хранят в состоянии. Поле показывает значение из состояния, а при каждом нажатии клавиши обновляет его. Такое поле называют управляемым: компонент в любой момент знает, что в нём написано.

function NameField() {
  const [name, setName] = useState('');

  return (
    <>
      <input value={name} onChange={(e) => setName(e.target.value)} />
      <p>Привет, {name || 'незнакомец'}!</p>
    </>
  );
}

Счётчик символов под полем

В поле для отзыва помещается 60 символов. Под ним написано, сколько ещё осталось, а кнопка отправки выключена, пока поле пустое. Отдельного состояния для счётчика нет: он считается из текста.

function Review() {
  const [text, setText] = useState('');
  const left = 60 - text.length;

  return (
    <>
      <input
        value={text}
        maxLength={60}
        onChange={(e) => setText(e.target.value)}
      />
      <p>Осталось символов: {left}</p>
      <button disabled={text.trim() === ''}>Отправить</button>
    </>
  );
}
